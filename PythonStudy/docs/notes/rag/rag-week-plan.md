# 第5周：RAG 基础 —— 精细化学习计划

> RAG（Retrieval-Augmented Generation）= 检索 + 生成。
> 让 LLM 在回答前先查资料，而不是只靠训练记忆。

---

## 为什么必须学 RAG？

| 问题 | 不用 RAG | 用 RAG |
|------|---------|--------|
| LLM 能回答你项目的代码规范吗？ | ❌ 没训练过 | ✅ 检索到规范后回答 |
| LLM 训练截止后的新知识？ | ❌ 不知道 | ✅ 检索到新文档 |
| LLM 回答能引用出处吗？ | ❌ 瞎编 | ✅ 引用检索到的片段 |
| 幻觉问题？ | 严重 | 大幅降低 |

**面试必问：** RAG 是 Agent 开发的核心技能，岗位 JD 几乎都有。

## Day 29（周一）：Embedding 原理

### 学习目标
理解 Embedding 是什么，为什么语义相近的向量距离近。

### 任务清单（拆到最小单位）

- [ ] **29.1** 理解 Embedding 概念（10min）
  - 文本 → 数字向量，语义相近 → 向量距离近
  - 类比：地图上"北京"和"上海"的经纬度比"北京"和"纽约"更近
- [ ] **29.2** 理解余弦相似度（10min）
  - 两个向量的夹角越小 → 越相似
  - cos(0°) = 1（完全相同），cos(90°) = 0（无关），cos(180°) = -1（完全相反）
- [ ] **29.3** 手写余弦相似度计算（20min）
  - 用纯 Python（不用 numpy）实现
  - 输入两个向量，输出相似度分数
- [ ] **29.4** 验证：用 3 组句子测试
  - "今天天气真好" vs "今天天气不错" → 应该高
  - "今天天气真好" vs "数据库索引优化" → 应该低
- [ ] **29.5** 输出学习笔记：一句话说清 Embedding 原理

### 必要性
这是 RAG 的地基。不知道向量怎么比相似度，后面检索全白学。

## Day 30（周二）：选 Embedding 模型 + 调通 API

### 学习目标
选定一个 Embedding 模型，调通 API，能把手写余弦相似度换成真实向量计算。

### 任务清单

- [ ] **30.1** Embedding 模型选型调研（15min）
  - 智谱 embedding-3、通义 text-embedding、本地 BAAI/bge-small-zh
  - 对比：价格、维度、中文效果、是否需要 GPU
- [ ] **30.2** 选定模型并获取 API Key（10min）
- [ ] **30.3** 用 Python 调用 Embedding API（20min）
  - 输入 3 句话，获取向量
  - 打印向量维度和前 5 个值
- [ ] **30.4** 用真实向量计算余弦相似度（15min）
  - 替换 Day 29 的手写假向量
  - 对比"语义相近"和"语义无关"的相似度差异
- [ ] **30.5** 代码提交

### 必要性
Embedding 模型是整个 RAG 系统的"眼睛"——它决定了检索质量的上限。选错模型后面全白做。

## Day 31（周三）：文本分片策略

### 学习目标
理解为什么需要分片，不同分片策略的影响。

### 任务清单

- [ ] **31.1** 理解分片概念（10min）
  - 为什么不能把整本书当一条向量？
  - 太长 → 语义稀释；太短 → 上下文丢失
- [ ] **31.2** 准备测试文档（5min）
  - 找一篇 2000 字左右的中文技术文章（或者用你自己的笔记）
- [ ] **31.3** 实现固定长度分片（20min）
  - 按字符数切：chunk_size=500，chunk_overlap=50
  - 打印每个片段的前 50 字预览
- [ ] **31.4** 实验不同参数（20min）
  - chunk_size: 200 / 500 / 1000
  - chunk_overlap: 0 / 50 / 100
  - 记录每种组合的片段数和效果
- [ ] **31.5** 输出结论：最佳参数是什么？为什么？

### 必要性
分片是 RAG 工程里最容易被忽视但影响最大的环节。切不好，后面检索全是垃圾。

## Day 32（周四）：文档加载 + 分片脚本

### 学习目标
写一个完整的文档加载→分片脚本，支持 .md 文件。

### 任务清单

- [ ] **32.1** 实现 Markdown 文件加载（10min）
  - 读取 .md 文件，返回纯文本
  - 处理文件不存在、编码错误
- [ ] **32.2** 封装分片函数（15min）
  - 输入：文本 + chunk_size + chunk_overlap
  - 输出：片段列表
  - 加入 Token 估算（中文字符 / 1.5 ≈ tokens）
- [ ] **32.3** 加入统计信息（10min）
  - 总片段数、平均长度、Token 估算
- [ ] **32.4** 准备 RAG 知识库文档（20min）
  - 用你熟悉的领域写 3-5 篇 .md 文档（如 Python 编码规范、API 设计原则等）
  - 每篇 500-1000 字
- [ ] **32.5** 跑通完整流程：加载文档 → 分片 → 统计 → 预览
- [ ] **32.6** 代码提交

### 必要性
知识库是 RAG 的"燃料"。没有知识库，RAG 就是空转。

## Day 33（周五）：向量数据库 Chroma

### 学习目标
安装 Chroma，把分片后的文本向量化并存入，实现检索。

### 任务清单

- [ ] **33.1** 理解向量数据库概念（10min）
  - 和传统数据库的区别：存的是向量，查的是相似度，不是精确匹配
- [ ] **33.2** 安装 Chroma（5min）
  - `pip install chromadb`
- [ ] **33.3** 创建集合 + 插入向量（20min）
  - 用 Day 32 的分片结果
  - 每条分片调 Embedding API → 存入 Chroma
  - 元数据：来源文件、片段序号
- [ ] **33.4** 执行检索（15min）
  - 输入自然语言查询 → 调 Embedding API → Chroma 检索 Top-3
  - 打印结果：相似度分数 + 片段内容 + 来源文件
- [ ] **33.5** 验证：用 3 个不同查询测试检索效果
- [ ] **33.6** 代码提交

### 必要性
Chroma 是 RAG 的"记忆库"。没有它，每次检索都要遍历所有向量——O(n) 变 O(log n)。

## Day 34（周六，5-6h）：端到端 RAG Pipeline

### 学习目标

### 任务清单

- [ ] **34.2** 支持增量添加文档（30min）
  - 新文档来了不重建整个库
- [ ] **34.3** 格式化检索结果（20min）
  - 输出：查询 + Top-K 结果（分数 + 内容 + 来源）
- [ ] **34.4** 用 5 个查询测试端到端（30min）
  - 记录检索准确率（人工判断是否相关）
- [ ] **34.5** 加入检索结果缓存（可选，30min）
  - 相同查询不重复调 Embedding API
- [ ] **34.6** 写一个简单的 CLI 入口（20min）
  - `python rag.py search "如何防止 SQL 注入"`
- [ ] **34.7** 代码提交 + 整理文档

### 必要性
