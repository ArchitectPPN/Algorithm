# Agent 是什么

> 把 Agent 这个概念彻底说清楚。不堆术语，不绕弯子。

---

## 一句话总结

> Agent = 大模型 + 自主调用工具 + 根据返回结果自主决策。

---

## 用点外卖来理解

**普通大模型**（只聊天）：
```
你：帮我点个附近评分最高的螺蛳粉
它：建议你打开外卖 APP，搜一下附近的螺蛳粉店，对比评分...
```
只会给建议，不会动手。

**Agent**：
```
你：帮我点个附近评分最高的螺蛳粉
它：
  1. 自己打开地图搜附近的螺蛳粉店
  2. 比对评分，选最高的
  3. 自己打开外卖平台下单
  4. 告诉你：已下单，预计 30 分钟到
```
自己做决定 + 自己动手 + 告诉你结果。

---

## 三个要素

| 要素 | 是什么 | 类比 |
|------|--------|------|
| 大模型 | 大脑，负责理解、推理、决策 | 人的大脑 |
| 工具 | 手脚，能干实际的事 | 人的手脚 |
| 自主决策循环 | 模型自己决定"现在干什么、下一步干什么" | 人的行动力 |

**三者缺一不可。** 没有工具就是只会聊天的客服，没有循环就是一次性的函数调用，没有大模型就是传统的自动化脚本。

---

## 核心：循环

普通调用是**一问一答**，Agent 是**循环**：

```
普通模式：
用户输入 → 模型输出 → 结束

Agent 模式：
用户输入 → 模型决定做什么 → 执行工具 → 拿到结果
         → 模型再决定做什么 → 执行工具 → 拿到结果
         → 模型认为任务完成了 → 输出最终回答 → 结束
```

这个循环就叫 **Agent Loop**。模型每次拿到工具返回的结果，会重新判断：任务完没完？没完就继续调工具，完了就输出最终答案。

## 实际执行过程

用户说："帮我看看项目里有没有 SQL 注入漏洞"

```
第 1 轮：模型决策 → 用 Grep 搜 "SELECT.*\${}" 之类拼接模式
         工具返回 → 找到 15 个可疑文件

第 2 轮：模型决策 → Read 最可疑的 3 个文件
         工具返回 → 文件完整内容

第 3 轮：模型决策 → 分析发现 2 处漏洞，用 Edit 修复
         工具返回 → 修复完成

第 4 轮：模型决策 → 确认修复完成，生成漏洞报告
         最终输出 → 告诉用户发现并修复了 2 个问题
```

**全程没人指挥。** 没人告诉它第一步搜什么、第二步读哪个文件、第三步怎么修。每一步都是模型根据上一步的结果自己决定的。

---

## 三个层次

不同人说的"Agent"，可能在讲不同层级：

```
第 1 层：单步工具调用
  "查一下北京天气" → 模型调一次 API → 返回结果
  严格说不算 Agent，只是 function calling

第 2 层：多步自主决策（真 Agent）
  "帮我重构 utils.py" → 模型自己分步读、改、测
  ← 这才是真 Agent

第 3 层：多 Agent 协作
  一个 Agent 拆任务 → 分发给多个 Agent 并行做 → 汇总
  第 2 层的升级版
```

市面上大多数人讨论的 Agent 是第 2 层。

---

## 市面上挂"Agent"名号的东西

| 产品 | 实际是什么 | 是真 Agent 吗 |
|------|-----------|--------------|
| 客服对话机器人 | 固定流程，用户选 1 选 2 | ❌ 是状态机 |
| RAG 问答系统 | 检索文档 + 拼接 prompt | ❌ 增强版问答 |
| ChatGPT GPTs | 预设 prompt 的对话 | ❌ 没有工具调用循环 |
| Claude Code | 大模型 + 工具 + 循环 | ✅ |
| Cursor Agent | 大模型 + 工具 + 循环 | ✅ |

**判断标准：模型能不能自己做决策链，而不是人预设流程。**

---

## 相关概念

- **Function Calling**：Agent 中"调用工具"这一步的技术实现，是模型 API 的能力，不是 Agent 的全部
- **MCP**：工具来源的标准化协议，让 Agent 能接入各种外部工具
- **Agent Loop**：Agent 的核心循环，模型反复"决策 → 执行 → 拿到结果 → 再决策"
- **子 Agent**：主 Agent 把部分任务交给另一个独立的 Agent 做，做完只收回结果，不污染主 Agent 的上下文
