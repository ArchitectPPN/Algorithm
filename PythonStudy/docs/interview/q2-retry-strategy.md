# Q2：JSON 解析失败时的重试上限怎么定

**分类**：工程认知　**难度**：⭐⭐

## 考察点

追问 Q1 的延伸问题。表面问重试次数，实际考察**工程权衡能力**——不是简单回答"有/没有上限"，而是体现对「无限重试的危害」和「重试上限怎么定」的理解。核心要回答三点：**为什么必须有上限**、**上限怎么定**、**超过上限怎么办**。

## 答题思路

### 一、为什么必须有上限

不设上限的后果：

1. **成本失控**：每次重试都要调一次模型 API，长输入 + 长输出场景，几次重试就烧掉几块钱
2. **延迟爆炸**：模型单次响应 5-30 秒，无限重试用户体验崩盘
3. **死循环风险**：模型可能稳定输出错误的格式（schema 设计有问题、prompt 不清晰），重试多少次都一样
4. **级联故障**：如果是被上层调用（如子 agent），无限重试会拖死整个任务链

### 二、重试上限怎么定

不是拍脑袋给个数字，要结合三个维度：

**1. 按场景分级**

| 场景 | 上限 | 理由 |
|------|------|------|
| 交互式 CLI（用户在等） | 2-3 次 | 延迟敏感，超过就反馈给用户重写 prompt |
| 后台批处理 | 5-10 次 | 延迟容忍，多试几次值得 |
| 子 agent 内部调用 | 2 次 | 不能让子 agent 拖死父任务 |
| 流式输出 | 1 次 | 流式重试代价高，直接失败回退非流式 |

**2. 按失败类型区分**

```python
def should_retry(error, attempt) -> tuple[bool, str]:
    # 1. 格式错误（markdown 包裹、尾逗号）→ 本地修复，不重试模型
    if isinstance(error, FormatError):
        return False, "走 repair_json 本地修就行"
    # 2. Schema 校验失败（字段缺失、类型错误）→ 重试，带上错误信息
    if isinstance(error, ValidationError):
        if attempt < 3:
            return True, f"字段错误：{error}"
    # 3. 完全不是 JSON（模型在闲聊）→ 重试 1 次，再不行就 fail fast
    if isinstance(error, NoJSONError):
        return attempt < 1, ""
    # 4. 截断（max_tokens 不够）→ 不重试，直接提示用户调大 token
    if isinstance(error, TruncationError):
        return False, "输出被截断，请增大 max_tokens"
```

**核心思想**：能本地修复的不重试模型，只对「格式对了但内容不对」的情况重试，且**每次重试都要带新信息**。

**3. 配合退避策略**

```python
import time, random

for attempt in range(max_retries):
    try:
        yield attempt
    except RetryableError:
        if attempt == max_retries - 1:
            raise
        delay = base_delay * (2 ** attempt) + random.uniform(0, 1)
        time.sleep(delay)
```

### 三、超过上限怎么办

1. **返回部分结果 + 错误信息**：能解析出部分字段就返回部分，标记 `partial=True`
2. **回退到更强模型**：弱模型解析失败时切到更强模型重试一次
3. **降级到非结构化输出**：JSON 解析不出就返回原始文本，让上层应用处理
4. **明确失败上报**：日志记录失败的输入/输出/错误

## 答题模板

> 重试必须有上限，原因有三：成本、延迟、死循环风险。
>
> 具体定多少，我会按场景分：
> - 交互式场景 2-3 次（用户在等）
> - 后台批处理 5-10 次（延迟容忍）
> - 子 agent 内部 2 次（不拖死父任务）
>
> 而且不是无差别重试：
> 1. **格式错误本地修复**，不重试模型
> 2. **Schema 校验失败**才重试，且每次带错误信息回喂模型
> 3. **截断**直接失败，提示调大 max_tokens
>
> 超过上限走降级：返回部分结果 → 切更强模型 → 返回原始文本 → 明确上报。
>
> 本质是：重试不是"再来一次"，而是"带新信息的修正尝试"。

## 追问预案

**Q: 为什么是 3 次不是 5 次？**
A: 经验值 + 概率论。如果模型一次成功率 90%，3 次成功率 ≈ 99.9%。如果 3 次都失败，大概率不是随机错误而是系统性问题，再试也没用

**Q: 怎么知道是"系统性问题"而不是"运气不好"？**
A: 看错误模式：
- 每次错误都一样 → 系统性问题，停
- 每次错误不一样 → 随机错误，可继续
- 错误逐渐收敛 → 继续
- 错误振荡（A→B→A）→ 停

**Q: 重试时要不要改 prompt？**
A: 要。第 2 次附上错误信息，第 3 次附上正确示例，第 4 次换更强模型
