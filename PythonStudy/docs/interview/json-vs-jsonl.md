# JSON vs JSONL

> `.json` 是"整存整取"的完整档案，`.jsonl` 是"流水账"式的逐行记录。

---

## 一句话区分

- **`.json`**：整个文件是一个完整的、嵌套的大对象（`{` 开头，`}` 结尾）
- **`.jsonl`**：每一行是一个独立的 JSON 对象，用换行符分隔

---

## 核心差异对比

| 维度 | JSON (`.json`) | JSONL (`.jsonl`) |
|------|----------------|-------------------|
| **文件结构** | 整个文件是一个完整嵌套对象 | 每行一个独立 JSON 对象 |
| **读取方式** | 全量加载，必须读进内存解析成整体 | 流式加载，按行读取，读一行解析一行 |
| **写入方式** | 覆写——追加新数据要读出旧内容、修改后整体重写 | 追加——直接在末尾新起一行写入 |
| **适用场景** | 配置参数、一次性完整快照、数据量小不频繁改动的状态 | 日志流、实时数据管道、流式生成的对话历史 |

---

## AI Agent 中为什么两种都有

分工不同：

### `.jsonl` 用于"实时流水账"（消息流）

Agent 流式输出时，每条消息、每次工具调用结果**立刻**以一行 JSON 追加到 `.jsonl` 文件。

好处：
- 即使 Agent 中途崩溃，已写入的行也完好无损
- 流式记录，性能高
- 逐行解析，不需要全量加载

### `.json` 用于"结算单"（状态快照/元数据）

Agent 把整个会话的状态（上下文压缩后的摘要、Token 计数、项目路径映射等）一次性保存成 `.json` 文件。

好处：
- 数据有整体性（嵌套树状结构）
- 必须作为完整整体读取

---

## 肉眼快速分辨

- **`.json`**：第一行通常是 `{`，最后一行是 `}`，中间只有一个大的整体
- **`.jsonl`**：每一行都以 `{` 开头、`}` 结尾，行数 = 消息条数

---

## 实用建议

- **导出对话记录处理**：`.jsonl` 更方便，逐行读取解析，不用等全量加载
- **自己写 Agent 记录长对话**：强烈推荐 `.jsonl` 存消息流，性能和可靠性都好
- **存配置/状态快照**：用 `.json`，整体性强，读写方便
