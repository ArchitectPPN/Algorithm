# Q4：何时应该压缩？Claude Code 和 Cursor 怎么限制上下文窗口

**分类**：上下文管理　**难度**：⭐⭐⭐

## 考察点

考察**对生产级 Agent 上下文管理的工程认知**。要回答清楚三件事：何时压缩的信号体系、Claude Code 和 Cursor 的具体策略、两者的设计差异。

## 答题思路

### 一、何时压缩：三类信号

**1. 量化信号（硬触发）**

| 指标 | 经验阈值 | 说明 |
|------|---------|------|
| Token 占窗口比 | 60%-70% | 留 30% 给模型输出和后续工具结果 |
| 绝对 token 数 | 80K-120K | 即使窗口 200K，超过这个量效果开始下滑 |
| 单轮工具结果长度 | > 2000 token | 摘要化处理 |
| 历史轮数 | > 20-30 轮 | 即使总 token 没超，轮数过多也会稀释注意力 |

**2. 行为信号（软触发）**

- **遗忘早期指令**：用户说"用 TypeScript"，10 轮后模型开始写 Python
- **重复调用工具**：刚 Read 过的文件又 Read 一次
- **答非所问**：用户问 A，模型答 B
- **重复输出/绕圈**：工具调用陷入 A→B→A→B 循环

**3. 任务边界信号（机会触发）**

最便宜的机会点——**任务阶段性完成时**主动压缩：
- 一个子任务完成 → 把过程压成一句结论
- 一个文件改完 → 把 Read 的内容丢弃
- 用户切换话题 → 旧话题过程可以全部摘要

### 二、Claude Code 怎么限制上下文

**1. 自动压缩（Auto-Compact）**
- 阈值：占窗口 ~92% 时自动触发
- 机制：调一次模型对早期对话做摘要
- 保留：最近若干轮 + 工具调用结果的关键信息

**2. 工具结果大小控制**
- Read 工具默认只读 2000 行
- Grep/Glob 结果默认限制返回条数
- Bash 输出超过一定长度会截断

**3. 子 Agent 隔离（最关键）**
```
主 agent 上下文：任务目标 + 子 agent 返回的结论
                ↓
        派生子 agent（独立上下文）
                ↓
        只把结论返回主 agent
```

**4. 用户可见的上下文状态**
- UI 上显示当前上下文占用百分比
- 用户可以 `/clear` 主动清空、`/compact` 主动压缩

### 三、Cursor 怎么限制上下文

**1. 代码库语义检索（关键差异）**
- 仓库代码预先做 embedding 索引
- 用户问题时，**检索最相关的代码片段**（top-k）
- 只把相关片段塞进上下文，而不是整个文件

**2. @-mentions 显式注入**
- `@filename`、`@文件夹`、`@docs` 显式加入上下文
- 用户主动控制上下文内容

**3. Tab 补全 vs Chat 分离**
- Tab 补全：极短上下文（当前文件 + 邻近文件），速度优先
- Chat：较长上下文，质量优先

### 四、对比表

| 策略 | Claude Code | Cursor |
|------|-------------|--------|
| Token 阈值触发压缩 | 92% | 按文件数/轮数 |
| 工具结果摘要化 | ✅ | ✅ |
| 子 agent 隔离上下文 | ✅（并行+流式） | ✅ |
| 用户可见上下文占用 | ✅（百分比） | ✅（预览） |
| 向量检索代码库 | ❌（靠 Glob/Grep） | ✅（核心） |
| 持久化指令文件 | ✅（CLAUDE.md） | ✅（.cursorrules） |

## 答题模板

> 何时压缩分三类信号：
> 1. **量化信号**：token 占窗口 60-70% 硬触发（Claude Code 是 92%，因为它还用其他手段降占用）
> 2. **行为信号**：模型开始遗忘指令、重复工具调用、陷入循环——软触发
> 3. **任务边界信号**：子任务完成时主动压缩——最便宜的机会点
>
> Claude Code 和 Cursor 的核心思路都是**「不靠塞更多，靠更聪明地选」**：
> - 工具结果摘要化、文件用 diff 而非全文
> - 子 agent 隔离上下文，主 agent 只收结论
> - 持久化指令写到文件，按需读不常驻
>
> 差异点：Cursor 额外用**向量检索**做代码库语义查找；Claude Code 更依赖 Glob/Grep + 子 agent 的组合。

## 加分项

- 明确区分三类压缩信号（量化/行为/任务边界），而不是只回答阈值
- 提到子 agent 是"上下文隔离舱"的设计哲学
- 对比 Cursor 的向量检索 vs Claude Code 的 Glob/Grep

## 追问预案

**Q: 为什么 Claude Code 用 92% 而不是 70%？**
A: 因为它还有多层兜底——工具结果大小控制、子 agent 隔离、文件缓存。70% 是"只靠压缩"的保守值，92% 是"多策略叠加"的激进值

**Q: 压缩本身会不会丢关键信息？**
A: 会，所以让**模型自己选**关键信息比规则截断更聪明；压缩后保留可恢复路径；重要决策单独标记不可压缩

**Q: 子 agent 上下文怎么管？**
A: 任务短（完成单一任务就退出）+ 可丢弃（失败时主 agent 只收错误信息，过程全丢）——子 agent 是"上下文压力的隔离舱"
