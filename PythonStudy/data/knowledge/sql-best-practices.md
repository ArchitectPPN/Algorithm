# 数据库操作规范

## SQL 注入防护

- 永远使用参数化查询，禁止拼接 SQL 字符串
- 错误示例：`f"SELECT * FROM users WHERE id = {user_id}"` ❌
- 正确示例：`cursor.execute("SELECT * FROM users WHERE id = %s", (user_id,))` ✅
- ORM 框架（SQLAlchemy/Django ORM）默认参数化，但仍需注意原生 SQL
- 输入校验是第一道防线，参数化查询是最后一道

## 索引优化

- WHERE 条件列建索引，JOIN 关联列建索引
- 联合索引遵循最左前缀原则：`INDEX(a, b, c)` 可覆盖 `a`、`a,b`、`a,b,c`
- 避免在索引列上使用函数：`WHERE YEAR(created_at) = 2024` ❌ → `WHERE created_at >= '2024-01-01'` ✅
- 查询前用 EXPLAIN 分析执行计划，确认走了索引
- 单表索引不超过 5 个，过多会影响写入性能

## 事务管理

- 写操作必须使用事务，确保原子性
- 事务范围尽量小，不要在事务中做耗时操作（如网络请求）
- 读操作一般不需要事务（除非需要可重复读）
- 避免长事务：持有锁时间越长，死锁概率越高
- 事务失败要回滚，不要依赖应用层重试

## 查询优化

- 避免 SELECT *，只查需要的列
- 大量数据分页查询：`LIMIT offset, size`，offset 大时改用游标分页
- 子查询改 JOIN：多数场景 JOIN 性能更好
- 避免在循环中执行查询（N+1 问题），改用批量查询
- 使用连接池，不要每次请求新建连接

## 数据安全

- 密码必须哈希存储（bcrypt/argon2），禁止明文或 MD5
- 敏感数据加密存储（身份证、手机号）
- 数据库连接信息不要硬编码，使用环境变量
- 定期备份，备份文件加密存储
- 生产环境禁止外网直连数据库
