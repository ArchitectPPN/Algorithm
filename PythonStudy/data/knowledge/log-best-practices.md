# 日志规范

## 日志级别

- DEBUG：调试细节，默认关闭，排查问题时临时开启
- INFO：关键业务事件（登录成功、订单创建），记录主流程
- WARNING：异常但不影响主流程（重试成功、缓存未命中）
- ERROR：业务/系统错误，需要人工关注（调用失败、数据异常）
- 禁止把敏感信息打到日志（密码、Token、身份证号）

## 日志内容

- 每个日志带时间戳、日志级别、模块名、请求 ID
- 记录关键参数，但大对象只记录摘要，不整对象打印
- 异常日志必须包含堆栈（traceback），光记 message 无法定位
- 关联上下文：一次请求的所有日志共用同一个 trace_id 便于串联

## 日志框架

- Python 用标准库 logging + TimedRotatingFileHandler
- 不直接用 print 打日志，print 无法分级、无法落地文件
- 配置统一格式化：`时间 级别 模块:消息`
- 日志目录权限收紧，防止被篡改

## 日志采样与成本

- 高并发接口的 DEBUG 日志要采样，全量打会拖垮性能
- 定期归档历史日志，控制单机磁盘占用
- ERROR 日志接入告警（企业微信/钉钉/邮件），及时响应
- 日志保留周期按合规要求（一般 180 天）

## 排错技巧

- 出问题先看 ERROR 级日志的 trace_id，再顺着找同 ID 的完整链路
- 线上临时加 DEBUG 日志要加开关，用完即关
- 排查问题时先看时间窗口，缩小到具体接口再深入
- 把"为什么出错"记录下来，比"出了什么错"更有价值
