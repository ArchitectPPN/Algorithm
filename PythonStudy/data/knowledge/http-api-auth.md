# HTTP API 认证与安全

## 认证方式选择

- 内部服务优先用 Token（JWT），对外公开接口用 OAuth2.0
- JWT 有效期要短（15 分钟以内），配合刷新令牌延长会话
- 不要自己实现加密算法，用成熟库（PyJWT / authlib / Keycloak）
- 令牌不要放在 URL 里，放 Authorization 请求头

## 接口鉴权

- 每个接口都要做鉴权，默认拒绝，白名单放行
- 角色权限用 RBAC，接口级别用装饰器/中间件统一校验
- 权限校验失败返回 401 未认证 / 403 无权限，不要返回 200
- 敏感操作（删除、转账）要做二次验证，防止越权

## 请求安全

- HTTPS 必须，禁止明文 HTTP 传输
- 设置请求体大小限制，防止超大 payload 攻击
- 对登录接口做限流（每 IP 每分钟 5 次），防止暴力破解
- 校验 Content-Type 和 Content-Length，拒绝异常请求

## 防重放攻击

- 给每个请求生成唯一请求 ID，服务端记录已消费的 ID
- 使用时间戳校验，过期请求直接拒绝（5 分钟窗口）
- 幂等接口用相同的请求 ID 返回缓存结果
- 防重放和幂等是两回事：防重放拒绝重复，幂等保证重复不报错

## 密钥管理

- API key 存服务端环境变量，不要提交到代码仓库
- 密钥轮换机制：定期更换，支持新旧密钥并存过渡
- 日志中禁止打印完整令牌和密钥，只记录脱敏后的尾巴
- 泄露的密钥立即吊销，并排查泄露时间窗口内的请求
